# 0.2.6 可靠性边界

## 本次改进

- 修复异步Wi-Fi启动时误判无凭据、自动配网恢复后不退出的问题；手动配网保持开放，手机使用热点时不主动重连，管理路由不重复注册。
- 天气下载与JSON校验移到后台；主循环只绘制有效缓存。正文最多24KB，失败保留旧值并60秒重试；启动预热一次，后续仅天气模式按设置刷新。
- 天气显示和进度时钟共用系统异步SNTP，不再由天气绘图同步访问DNS/UDP。
- 额度/天气客户端增加10秒传输预算和32KB总接收上限，单次连接/读取3秒不变。DNS仍用core有界解析并在后台执行，可能另加等待，不能把10秒当作含DNS的全请求硬上限。
- 显式处理任务创建失败、增加只读主循环/heap/任务栈状态、初始化预警底色；配网保存设置15秒专用连接超时，扫描入口转到手填页。

## 测试与限制

`py -3 -B -m unittest discover -s clock_rom -p "test_*.py"`：20项源码契约检查。

Windows安装MSVC C++ Build Tools后，`py -3 maintenance/native_reliability_test.py` 会执行实际C++解析/传输代码的8组天气夹具、11项传输断言；时间/socket/String由主机适配器模拟，不代表ESP32驱动或无线故障实测。编译器输出保留在新的build目录中。

只读状态API包含`loop_max_ms`、`uptime_ms`、`free_heap`、`min_free_heap`、`poll_worker_ready`、任务剩余栈、天气状态及解析自检数。生产环境不自动触发音效、不更改用户设置、不用无条件重启掩盖问题。

仍有边界：底层同步WebServer处理慢请求可能阻塞；浏览器fetch尚无主动截止；配网提交仍有同步等待；跨NVS/EEPROM设置不保证掉电原子性。只限可信局域网，不暴露公网。未修改锁定第三方依赖来冒险解决这些问题。

写入校验、短期HTTP观察、真实屏幕/音效、断网恢复及长期稳定性是不同验证范围，不能互相替代。现有界面与提醒规则不变，后续新交互先预览确认，再实施。

0.2.6目标设备已完成写入/独立校验/8MB复读，随后2分钟及追加6分钟只读观察通过：Wi-Fi、额度与天气正常，解析自检8项通过，无重启，最大主循环耗时72ms；连接回收后末段可用heap约234KB、波动4字节。未自动切换用户模式、试听、断开路由或更改设置；这不是长期/故障注入测试结论。
